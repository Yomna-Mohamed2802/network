1.2 What is an algorithm?

  • The word "Algorithm" comes from the name of the mathematician Mohammed ibn Musa al-Khwarizmi.كلمة Algorithm جاية من اسم العالم المسلم محمد بن موسى الخوارزمي.
  • Algorithm: a sequence of instructions describing how to solve a problem.الـ Algorithm: خطوات مرتبة بتوصف إزاي نحل مشكلة.
  • Book (exam-ready) definition: a finite, definite, effective procedure for solving a problem for every valid input from the specified input domain.تعريف الكتاب للامتحان: خطوات محدودة (بتخلص)، وواضحة، وينفع تتنفذ، وبتحل المشكلة لأي input صحيح من الـ input domain.
  • It accepts valid input and produces the required output.بتاخد input صحيح وتطلّع الـ output المطلوب.

1.4 How to write an algorithm

  • An algorithm can be described in three ways: natural language (like English; every statement must be definite), a flowchart (graphic; works well when the algorithm is small and simple), or pseudocode (written like a program, resembling a language such as Pascal).تلات طرق: بالكلام العادي (بشرط كل جملة تبقى واضحة)، أو flowchart رسم (كويس للـ algorithms الصغيرة البسيطة)، أو pseudocode (شبه كود برنامج زي لغة Pascal).
  • Problem-solving pipeline: Problem definition → Input specification → Algorithm design → Correctness proof → Efficiency analysis → Implementation & testing.خطوات حل أي مشكلة: نعرّف المشكلة ← نحدد الـ input ← نصمم الـ algorithm ← نثبت إنها صح ← نحلل كفاءتها ← ننفذها ونجربها.
  • The input domain is part of the specification: binary search, for example, is correct only for a sorted array.الـ input domain جزء من تعريف المشكلة. مثلاً الـ binary search صح بس لو الـ array مترتبة، ومن غير الشرط ده ممكن تطلّع إجابة غلط.

1.6 The RAM model

  • The Random-Access Machine (RAM) model is a theoretical framework used to analyze the efficiency of an algorithm independently of specific hardware or programming language.الـ RAM model جهاز "تخيلي" بنحلل عليه الـ algorithm، عشان النتيجة متتأثرش بنوع الجهاز ولا اللغة.
  • Every basic operation (+, −, ×, /, assignment, comparison, memory access) takes one time step (constant time).كل عملية بسيطة (جمع، طرح، مقارنة، تخزين، قراية من الميموري) = خطوة واحدة.
  • Instructions run sequentially, one after another (no parallel work).الأوامر بتتنفذ واحد ورا التاني، مفيش حاجتين في نفس الوقت.
  • Loops and function calls are not single steps: their cost depends on how many times they run.الـ loop أو استدعاء دالة مش خطوة واحدة؛ تكلفتهم على حسب عدد مرات التنفيذ.
  • Purpose: abstract machine-dependent details and focus on how the cost grows with n; choose a basic operation that best represents the running time.الهدف: نشيل تفاصيل الجهاز ونركز على إزاي التكلفة بتكبر مع n، ونختار "العملية الأساسية" اللي بتمثل وقت التشغيل.

1.9 Example 2: Euclid's algorithm (GCD)

  • Euclid's algorithm is an efficient method for computing the greatest common divisor (GCD) of two integers.طريقة سريعة نجيب بيها القاسم المشترك الأكبر لرقمين.
  • Rule: gcd(m, n) = gcd(n, m mod n), repeat until the second number is 0; then the answer is the first number.القاعدة: gcd(m, n) = gcd(n, باقي قسمة m على n)، ونكرر لحد ما التاني يبقى صفر، والإجابة هي الرقم الأول.
EUCLID(m, n)
  while n ≠ 0 do
      r = m mod n
      m = n
      n = r
  return m

gcd(60, 24) → gcd(24, 12) → gcd(12, 0) = 12
60 mod 24 = 12، بعدين 24 mod 12 = 0، فالإجابة 12. الكتاب بيستخدم المثال ده عشان يوضح إن نفس المشكلة ممكن يبقى ليها algorithms مختلفة في السرعة جداً (مقارنةً بإننا نجرب كل الأرقام من الأصغر وننزل).

2.2 Example: maximum of n numbers

Algorithm Max_Arr(A, n)      // A is an array of size n
{
    max := A[1];
    for i := 2 to n do
        if A[i] > max then max := A[i];
    return max;
}
بنفترض إن أول عنصر هو الأكبر، ونقارن الباقي بيه واحد واحد. مثال المحاضرة: ‏[4,1,7,0,5,2,9,3,6,8] والـ max بقى 9. لو الـ array فيها n عنصر، الـ algorithm بتاخد حوالي n خطوة.

2.4 What is algorithm analysis?

  • Analysis of algorithms = an investigation of an algorithm's efficiency. The goal is to determine the cost of running an algorithm and how to reduce it.تحليل الـ algorithm = نقيس كفاءتها: بتكلف قد إيه، وإزاي نقلل التكلفة.
  • Cost is expressed as complexity: time complexity (how much time the program will take) and space complexity (how much memory it will consume).التكلفة اسمها complexity، ونوعين: وقت (هياخد قد إيه) ومساحة (هياكل ميموري قد إيه).
  • Time efficiency mainly depends on the input size n, so it is written as a function of n. Algorithms usually run longer as n grows, so we care how efficiency scales.الوقت بيعتمد على حجم الـ input ‏(n)، فبنكتبه كدالة في n، ويهمنا بيكبر إزاي لما n تكبر.
  • Analysis framework: measuring the input size; measuring running time; orders of growth; worst-case, best-case and average-case efficiency.إطار التحليل 4 حاجات: حجم الـ input، ووقت التشغيل، ورتبة النمو، والحالات التلاتة (أسوأ، أحسن، متوسط).

2.5 Asymptotic notations

Asymptotic notations are the mathematical notations used to describe the running time of an algorithm when the input tends towards a particular or limiting value.رموز رياضية بتوصف وقت الـ algorithm لما الـ input يكبر جداً.

  • Example from the lecture (bubble sort): already sorted array → linear time (best case); reversed array → quadratic time (worst case); neither → average time.مثال الـ bubble sort: لو مترتبة أصلاً تبقى أسرع حالة (خطية)، لو مقلوبة تبقى أبطأ حالة (تربيعية)، وغير كده متوسط.
  • Big-O (O): the upper bound of the running time.
    O(g(n)) = { f(n) : there exist positive constants c and n₀ such that 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀ }الحد الأعلى: الدالة f مش بتعدّي c·g بعد نقطة n₀. يعني "أسوأ من كده مش هيحصل".
  • Omega (Ω): the lower bound.
    Ω(g(n)) = { f(n) : there exist positive constants c and n₀ such that 0 ≤ c·g(n) ≤ f(n) for all n ≥ n₀ }الحد الأدنى: f دايماً فوق c·g بعد n₀. يعني "أسرع من كده مش هيحصل".
  • Theta (Θ): encloses the function from above and below (tight bound).
    Θ(g(n)) = { f(n) : there exist positive constants c₁, c₂ and n₀ such that 0 ≤ c₁·g(n) ≤ f(n) ≤ c₂·g(n) for all n ≥ n₀ }حد مضبوط: f محصورة بين c₁·g وc₂·g. يعني Θ = O وΩ مع بعض.
زيادة من الكتاب: فيه كمان little-o: ‏f = o(g) لو f/g ← 0 (f أصغر بكتير، زي n = o(n²)). وlittle-omega: ‏f = ω(g) لو f/g ← ∞ (f أكبر بكتير). ومثال على f = O(g) ومش Θ(g): ‏f = n وg = n².

Rules for simplifying (book)

  • Drop constant factors: Θ(7n) = Θ(n).نشيل المعامل الثابت.
  • Keep the dominant term: Θ(n² + n + 1) = Θ(n²).نسيب الحد الأكبر بس.
  • Log bases differ only by a constant: log₂ n = Θ(log₁₀ n).أساس الـ log مش فارق.
  • Polynomial beats logarithmic; exponential beats polynomial.n^k أكبر من log n، و2ⁿ أكبر من أي n^k.

2.6 Time complexity

  • Running time is affected by many factors other than the algorithm: CPU speed, amount of main memory, specialized hardware (graphics card), operating system, system configuration (virtual memory), programming language, and the implementation.الوقت الحقيقي بيتأثر بحاجات كتير ملهاش دعوة بالـ algorithm: سرعة البروسيسور، والرامات، وكارت الشاشة، ونظام التشغيل، والإعدادات، واللغة، وطريقة كتابة الكود.
  • So instead of timing an algorithm, we count the number of instructions it performs: T(n).عشان كده بدل ما نقيس بالساعة، بنعدّ عدد الخطوات ونسميه T(n).
  • It is difficult to count every operation exactly, so we focus on the basic operation; the number of times it runs is proportional to the running time.بدل ما نعدّ كل حاجة بالظبط، نعدّ العملية الأساسية (زي المقارنة في البحث)، لأن عددها بيمشي مع الوقت.
  • Growth-rate function: measures how the time requirement grows as the input size grows. We usually measure the worst-case time.دالة النمو بتوصف الوقت بيزيد إزاي مع n، وعادةً بنحسب أسوأ حالة.

2.7 Frequency count method

Count how many times each statement runs; T(n) is the total. Space S(n) counts the memory words used.نكتب جنب كل سطر عدد مرات تنفيذه ونجمع = T(n). والمساحة S(n) = عدد المتغيرات والخانات اللي استخدمناها.

Example A: factorial

Algorithm factorial(n)
{
    f = 1;                    1
    if (n > 0)                1
        for (i = 1 to n)      n + 1
            f = f * i;        n
    return f;                 1
}                     T(n) = 2n + 4      S(n): n, f, i → 3 words = O(1)
سطر الـ for بيتنفذ n+1 مرة (n مرة بيدخل، ومرة أخيرة بيختبر الشرط ويطلع). جسم الـ loop n مرة. المجموع 1 + 1 + (n+1) + n + 1 = 2n + 4 → O(n). المساحة 3 متغيرات بس (n وf وi)، فـ S(n) = 3 → O(1).

Example B: adding two n×n matrices

Algorithm Add_matrix(A, B, n)
{
  for (i = 1 to n)                 n + 1
    for (j = 1 to n)               n(n + 1)
      C[i,j] = A[i,j] + B[i,j];    n·n
}                    T(n) = 2n² + 2n + 1     S(n) = 3n² + 3
الـ for الخارجية n+1. الداخلية بتتعمل n مرة وكل مرة n+1 → n(n+1) = n² + n. سطر الجمع n². المجموع n+1 + n²+n + n² = 2n² + 2n + 1 → O(n²). المساحة: 3 مصفوفات A وB وC كل واحدة n² خانة = 3n²، و3 متغيرات n وi وj → S(n) = 3n² + 3 → O(n²).

4.3 Selection sort

  • Scan the array to find its smallest element and swap it with the first element.ندوّر على أصغر عنصر ونبدّله مع أول خانة.
  • Then, starting with the second element, find the smallest among the elements to its right and swap it with the second element; continue.بعدين من تاني خانة، ندوّر على أصغر عنصر في الباقي ونبدّله مع التانية، وهكذا.

// Input: an array A[0..n−1] of orderable elements
// Output: A sorted in ascending order
for i ← 0 to n − 2 do
    min ← i
    for j ← i + 1 to n − 1 do
        if A[j] < A[min]  min ← j
    swap A[i] and A[min]

4.5 Binary search

  • The array must already be sorted (assume ascending).لازم الـ array تكون مترتبة.
  • Compare the key with the middle element. Three cases: key < middle → search the first half; key = middle → found; key > middle → search the second half.نقارن بالنص: لو أصغر نروح النص الشمال، لو يساوي لقيناه، لو أكبر نروح اليمين.
Binary-Search(A, key) {                      // iterative
    low = 0;  high = A.length − 1;
    while (high >= low) {
        mid = (low + high) / 2;
        if (key < A[mid])       high = mid − 1;
        else if (key == A[mid]) return mid;
        else                    low = mid + 1;
    }
    return −1;
}

Binary-search(A, low, high, key):            // recursive
    if high < low then return −1
    mid = (low + high) / 2

    else if A[mid] > key then Binary-search(A, low, mid − 1, key)
    else Binary-search(A, mid + 1, high, key)

4.6 Merge sort

  • Closely follows divide and conquer. Each step sorts a subarray A[p..r], starting with the whole array.بيمشي على فكرة قسّم واحكم بالظبط، وكل مرة بيرتّب جزء A[p..r].
  • Divide A[p..r] into two adjacent halves (n/2 each) at q = ⌊(p + r)/2⌋.نقسم من النص عند q.
  • Conquer by sorting A[p..q] and A[q+1..r] recursively with merge sort.نرتّب كل نص بنفس الطريقة.
  • Combine by merging the two sorted halves back into A[p..r].ندمج النصين المترتبين في array واحدة مترتبة.
MERGE-SORT(A, p, r)
1  if p ≥ r                         // zero or one element?
2      return
3  q = ⌊(p + r)/2⌋                  // midpoint
4  MERGE-SORT(A, p, q)              // T(n/2)
5  MERGE-SORT(A, q + 1, r)          // T(n/2)
6  // merge A[p:q] and A[q+1:r] into A[p:r]
7  MERGE(A, p, q, r)                // Θ(n)

MERGE(A, p, q, r)
 1  n1 ← q − p + 1 ;  n2 ← r − q
 2  create arrays L[1..n1+1] and R[1..n2+1]
 3  for i ← 1 to n1:  L[i] ← A[p + i − 1]
 4  for j ← 1 to n2:  R[j] ← A[q + j]
 5  L[n1 + 1] ← ∞ ;  R[n2 + 1] ← ∞          // sentinels
 6  i ← 1 ; j ← 1
 7  for k ← p to r
 8      if L[i] ≤ R[j]  then A[k] ← L[i];  i ← i + 1

5.2 Substitution method (expanding)

Expand the recurrence step by step and express it as a summation of terms depending only on n and the initial condition.نفكّ المعادلة خطوة خطوة لحد ما نشوف الـ pattern بعد k خطوة، وبعدين نخلي الـ k توصّلنا للـ base case.

خلي بالك: المحاضرة بتسمّي "فك المعادلة" substitution (الأمثلة تحت). الكتاب والسكشن بيستخدموا كمان "خمّن وأثبت" (guess and prove) وده في تاب Math وفي الـ Lab. الاتنين ممكن ييجوا.

Example 1: T(n) = T(n−1) + 1, T(1) = Θ(1)

T(n) = T(n−1) + 1
     = [T(n−2) + 1] + 1 = T(n−2) + 2
     = [T(n−3) + 1] + 2 = T(n−3) + 3
     = T(n−4) + 4
     ...
     = T(n−k) + k                      (step k)
base case: n − k = 1 → k = n − 1, T(1) = 1
T(n) = 1 + (n − 1) = n   → Θ(n)
كل مرة نعوّض T(n−1) بقيمتها (T(n−2) + 1). بعد k مرة الشكل T(n−k) + k. نوصل للـ base لما n − k = 1.

Example 2: T(n) = c + T(n/2)

T(n/2) = c + T(n/4),  T(n/4) = c + T(n/8)
T(n) = c + c + T(n/4)              step 2
     = 3c + T(n/2³)                step 3
     = k·c + T(n/2^k)              step k
T(1) is reached when n = 2^k → k = log₂ n, T(1) = 1
T(n) = c·log₂ n + 1   → Θ(log₂ n)
ده الـ binary search. بعد k خطوة الحجم n/2^k، ولما يبقى 1 يبقى k = log₂ n.

Example 3: T(n) = n + 3T(n/4), T(1) = 1

T(n/4) = n/4 + 3T(n/16),  T(n/16) = n/16 + 3T(n/64)
T(n) = n + 3[(n/4) + 3T(n/16)]   = n + 3(n/4) + 9T(n/16)            step 2
     = n + 3(n/4) + 9(n/16) + 27T(n/64)                              step 3
     = n + 3(n/4) + 3²(n/4²) + … + 3^(k−1)(n/4^(k−1)) + 3^k T(n/4^k)  step k
T(1) when n/4^k = 1 → k = log₄ n
T(n) = n[(3/4)⁰ + (3/4)¹ + … + (3/4)^(log₄n − 1)] + 3^(log₄ n)
     ≤ n · 1/(1 − 3/4) + n^(log₄ 3)  = 4n + n^0.79
     = 4n + O(n)  → O(n)
الحدود بتطلع n مضروبة في (3/4)^i، وده متتالية هندسية نسبتها 3/4 أقل من 1، فمجموعها ≤ 1/(1 − 3/4) = 4. والحد الأخير 3^(log₄ n) = n^(log₄ 3) ≈ n^0.79 أصغر من n. فالإجابة O(n).

5.3 Recursion-tree method

  • Each node represents the cost of a single subproblem.كل node = تكلفة مسألة صغيرة واحدة.
  • To get the total: (I) the cost of each node at depth i, (II) sum all nodes at depth i, (III) sum all per-level costs.نحسب تكلفة الـ node، ونجمع كل مستوى، ونجمع المستويات.
  • Total cost = cost of the leaf nodes + sum of the costs of each internal level.الإجمالي = تكلفة الأوراق + مجموع المستويات الداخلية.

Example 1: T(n) = 2T(n/2) + c

level costs: c, 2c, 4c, 8c, …, 2^k c          stops when n/2^k = 1 → n = 2^k
T(n) = c(2⁰ + 2¹ + … + 2^k) = c(2^(k+1) − 1) = c(2n − 1)  → O(n)
كل مستوى عدد الـ nodes بيتضاعف وكل واحدة تكلفتها c. المجموع متتالية هندسية نسبتها 2، ولما نعوّض 2^k = n يطلع c(2n − 1).

Example 2: T(n) = 2T(n/2) + n

Level 0:  n                              = n
Level 1:  n/2 + n/2                      = n
Level 2:  n/4 ×4                         = n
Level 3:  n/8 ×8                         = n
…         k = log n levels
internal levels = n·k,  leaves = 2^k = n
T(n) = n log n + n  → O(n log n)

Example 3: T(n) = 2T(n/2) + n²

Level 0: n²
Level 1: 2·(n/2)² = n²/2
Level 2: 4·(n/4)² = n²/4
internal = n²[(1/2)⁰ + (1/2)¹ + … + (1/2)^(k−1)] ≤ n² · 1/(1 − 1/2) = 2n²
leaves = 2^k = n
T(n) = n + 2n² → O(n²)
هنا كل مستوى أرخص من اللي قبله بالنص (لأن n متربعة)، فالمجموع ≤ ضعف أول مستوى. أول مستوى هو اللي مسيطر.

5.4 Master method

A "cookbook" method for recurrences of the form T(n) = a·T(n/b) + f(n), where a ≥ 1 and b > 1 are constants and f(n) is asymptotically positive.طريقة "وصفة جاهزة" لأي معادلة على الشكل ده: a = عدد الاستدعاءات (≥ 1)، b = بنقسم على كام (> 1)، f(n) = الشغل برّه الاستدعاءات.

Compare f(n) with n^(log_b a):
Case 1: f(n) = O(n^(log_b a − ε)) for some ε > 0          → T(n) = Θ(n^(log_b a))
Case 2: f(n) = Θ(n^(log_b a))                               → T(n) = Θ(n^(log_b a) · lg n)
Case 3: f(n) = Ω(n^(log_b a + ε)) for some ε > 0
        AND a·f(n/b) ≤ c·f(n) for some c < 1 (regularity)   → T(n) = Θ(f(n))
بالبلدي: (1) لو n^(log_b a) أكبر "بأُس" من f → الإجابة n^(log_b a). ‏(2) لو متساويين → نضرب في lg n. ‏(3) لو f أكبر "بأُس" (وشرط الـ regularity متحقق) → الإجابة f(n). "بأُس" (polynomially) يعني الفرق لازم يبقى n^ε، مش مجرد log.
  1. Extract a, b and f(n).طلّعي a وb وf(n).
  2. Determine n^(log_b a).احسبي n^(log_b a).
  3. Compare f(n) and n^(log_b a) asymptotically.قارني.
  4. Determine the case and apply it.حددي الحالة وطبّقي.

6.1 Quick sort idea

  • Pick an element called the pivot.نختار عنصر اسمه pivot (المحور).
  • Reorder the list so that all elements less than the pivot come before it and all greater come after it. After this partition operation the pivot is in its final position.نرتّب بحيث كل الأصغر منه شماله وكل الأكبر يمينه. بعد كده الـ pivot بيبقى في مكانه النهائي ومش هيتحرك تاني.
  • Recursively sort the sub-list of lesser elements and the sub-list of greater elements. Base case: lists of size 0 or 1.نعمل نفس الكلام على الجزء الشمال والجزء اليمين، ونقف لما الجزء يبقى فاضي أو عنصر واحد.
  • Divide: partition A[p..r] into A[p..q−1] (each ≤ A[q]) and A[q+1..r] (each ≥ A[q]). Conquer: sort both by recursive calls. Combine: no work needed, the subarrays are already sorted in place.التقسيم = الـ partition. الحل = recursion على الجزئين. الدمج = مفيش شغل خالص (عكس الـ merge sort اللي شغله كله في الدمج).
QUICKSORT(A, p, r)
1  if p < r
2      q = PARTITION(A, p, r)
3      QUICKSORT(A, p, q − 1)
4      QUICKSORT(A, q + 1, r)

PARTITION(A, p, r)                 // Lomuto: pivot = last element
1  x = A[r]
2  i = p − 1
3  for j = p to r − 1
4      if A[j] ≤ x
5          i = i + 1
6          exchange A[i] with A[j]
7  exchange A[i + 1] with A[r]
8  return i + 1

6.3 Performance of quick sort

The running time depends on whether the partitioning is balanced or unbalanced.السرعة بتعتمد على الـ partition: متوازن ولا لأ.

Part 4: recurrences from recursive code

T(n) = the time of the function on input n. Each recursive call becomes a T(...) term, and the non-recursive work becomes the added part.الـ recurrence هي معادلة بتوصف وقت الدالة بدلالة وقتها على input أصغر. كل استدعاء للدالة جوّه نفسها = حد T(...)، والشغل العادي (مقارنة، جمع، loop) = الحد اللي بنزوّده.

fact(n-1)                       → T(n) = T(n−1) + 1
fact(n/2)                       → T(n) = T(n/2) + 1
fact(n/2) + fact(n/2)           → T(n) = 2T(n/2) + 1
fact(n-1) + fact(n-2)           → T(n) = T(n−1) + T(n−2) + 1
fact(n-1) + fact(n-2) + a loop 1..n → T(n) = T(n−1) + T(n−2) + n
بصّي على اللي جوّه القوس في كل استدعاء: n−1 يبقى T(n−1)، و n/2 يبقى T(n/2). لو فيه استدعائين يبقى حدّين (ولو نفس الحجم نكتب 2T). والـ +1 هي الشغل الثابت (if + جمع + return). لو جوّه الدالة loop من 1 لـ n نكتب + n بدل + 1.
ملاحظة: في الكشكول فيه مثال fact(n/2) + fact(3n/2). كده الـ recurrence تبقى T(n/2) + T(3n/2) + 1، بس 3n/2 أكبر من n فالاستدعاء مش هيوصل للـ base case. غالباً المقصود 3n/4، اتأكدي من السكشن.

if r < 1 and the series is long:              ≤ a/(1 − r)
a = تكلفة أول مستوى، r = النسبة بين كل مستوى واللي قبله، h = عدد المستويات (ارتفاع الشجرة). لو r أكبر من 1 التكلفة بتكبر لتحت (آخر مستوى هو المهم). لو r أصغر من 1 التكلفة بتصغر (أول مستوى هو المهم).

1. T(n) = 2T(n/2) + 10

Show solution 
level 0:  1 node  × 10 = 10
level 1:  2 nodes × 10 = 20
level 2:  4 nodes × 10 = 40
...       r = 2,  h = log₂ n levels
sum = 10(2^h − 1)/(2 − 1) = 10(n − 1)  → O(n)
كل node بتتقسم لاتنين، فعدد الـ nodes بيتضاعف كل مستوى وكل node تكلفتها 10. الحجم بيتقسم على 2 لحد ما يوصل 1، فعدد المستويات log₂ n، و 2^(log₂ n) = n. فالمجموع 10(n − 1) → O(n).

2. T(n) = 3T(n/3) + n²

Show solution 
level 0:  n²
level 1:  3 × (n/3)² = n²/3
level 2:  9 × (n/9)² = n²/9
r = 1/3 < 1
sum ≤ n² / (1 − 1/3) = 3n²/2  → O(n²)
كل مستوى فيه nodes أكتر بس كل واحدة أصغر بكتير لأن الـ n متربعة. (n/3)² = n²/9، ومضروبة في 3 nodes = n²/3. التكاليف بتقل (r = 1/3)، فنستخدم a/(1 − r) والمجموع أقل من 1.5 n² → O(n²). يعني أول مستوى هو اللي مسيطر.

3. T(n) = T(n−1) + T(n−2) + 1

Show solution 
level 0: 1,  level 1: 2,  level 2: 4, ...   r = 2
height ≈ n (n goes down by 1 each level)
sum ≤ (2^n − 1)/(2 − 1) = 2^n − 1  → O(2ⁿ)
كل استدعاء بيعمل اتنين، فعدد الاستدعاءات بيتضاعف. والـ n بتقل بـ 1 بس كل مرة، فالشجرة طولها حوالي n. ده حد أعلى (الفرع بتاع n−2 بيخلص أسرع)، فنقول O(2ⁿ). ده سبب إن Fibonacci بالـ recursion بطيء جداً.

4. T(n) = T(n−1) + n

Show solution 
costs: n + (n−1) + (n−2) + ... + 1 = n(n+1)/2  → O(n²)
هنا مفيش تفرّع، الشجرة خط واحد. كل مستوى تكلفته حجمه، فبنجمع n + (n−1) + … + 1 بقانون n(n+1)/2.

Part 6: master method

T(n) = a·T(n/b) + n^d        (a ≥ 1, b > 1)
compare n^(log_b a) with n^d:
  log_b a > d  →  T(n) = O(n^(log_b a))
  log_b a < d  →  T(n) = O(n^d)
  log_b a = d  →  T(n) = O(n^d · log n)
a = عدد الاستدعاءات، b = بنقسم الحجم على كام، n^d = الشغل برّه الاستدعاءات. احسبي log_b a وقارنيه بـ d: اللي أكبر هو اللي يكسب. ولو متساويين نضرب في log n.

1. T(n) = 4T(n/2) + n

Show solution 
a = 4, b = 2, d = 1 → log₂ 4 = 2 > 1  → O(n²)
log₂ 4 = 2 لأن 2² = 4. الـ 2 أكبر من d = 1، فالحالة الأولى: O(n²).

2. T(n) = 4T(n/2) + n²

Show solution 
log₂ 4 = 2 = d  → O(n² log n)
متساويين، فبناخد n^d ونضرب في log n.

3. T(n) = 4T(n/2) + n³

Show solution 
log₂ 4 = 2 < 3  → O(n³)
الشغل برّه (n³) أكبر، فهو اللي يكسب.
غلطة كتابة في الكشكول: المثال مكتوب 4T(n/2) + 3 وبعدها "n² < n³ → O(n³)". الحل ده بتاع 4T(n/2) + n³. لو فعلاً + 3 (ثابت، d = 0) يبقى 2 > 0 والناتج O(n²).

4. Extended master: T(n) = aT(n/b) + n^d · log^k n

same three cases; only the equal case changes:
  log_b a = d  →  O(n^d · log^(k+1) n)
Show both examples 
T(n) = 2T(n/2) + n log n : a=2 b=2 d=1 k=1 → log₂ 2 = 1 = d → O(n log² n)
T(n) = 2T(n/8) + ∛n       : a=2 b=8 d=1/3 k=0 → log₈ 2 = 1/3 = d → O(n^(1/3) log n)
الـ k هي أُس الـ log في الشغل برّه. في الحالة المتساوية بنزوّد الـ log أُس واحد (k + 1). المثال التاني: log₈ 2 = 1/3 لأن 8^(1/3) = 2، و ∛n = n^(1/3)، فمتساويين و k = 0 → n^(1/3) log n.

Part 7: substitution method

Guess the answer, assume it holds for smaller inputs, put it in the recurrence, and find the constant k that makes it true.نخمّن الإجابة (مثلاً T(n) ≤ k log n)، ونفترض إنها صح للأحجام الأصغر، ونعوّض في المعادلة، ونشوف k لازم تبقى قد إيه عشان التخمين يفضل صح.

1. T(n) = T(n/2) + c → guess O(log n)

Show solution 
assume T(n/2) ≤ k log(n/2)
T(n) ≤ k log(n/2) + c = k(log n − 1) + c = k log n − k + c
     ≤ k log n   when  k ≥ c        → T(n) = O(log n)
log(n/2) = log n − 1 (أساس 2). عشان نوصل لـ k log n محتاجين الباقي (−k + c) يبقى ≤ 0، يعني k ≥ c.

2. T(n) = T(n−1) + c → guess O(n)

Show solution 
assume T(n−1) ≤ k(n−1)
T(n) ≤ k(n−1) + c = kn − k + c ≤ kn   when  k ≥ c   → O(n)
نفس الفكرة: الحد الزيادة (−k + c) لازم يبقى سالب أو صفر.

3. T(n) = T(n−1) + n → guess O(n²)

Show solution 
assume T(n−1) ≤ k(n−1)²
T(n) ≤ k(n² − 2n + 1) + n = kn² − 2kn + k + n
     ≤ kn²  when  −2kn + k + n ≤ 0  →  n ≤ k(2n − 1)  →  k ≥ n/(2n − 1)
n/(2n−1) ≤ 1 for n ≥ 1, so k = 1 works   → O(n²)
فكّي (n−1)² = n² − 2n + 1. الباقي بعد kn² لازم يبقى ≤ 0. اعزلي k: ‏k ≥ n/(2n − 1). القيمة دي دايماً ≤ 1، فـ k = 1 كفاية.

Part 8: proving f(n) = O(g(n))

f(n) = O(g(n)) means there are constants c > 0 and n₀ with f(n) ≤ c·g(n) for every n ≥ n₀. Trick: raise every term to g(n), then add the coefficients.التعريف: لازم نلاقي رقم c ورقم n₀ بحيث f(n) ≤ c·g(n) لكل n ≥ n₀. الطريقة السهلة: كل حد في f نكبّره لحد ما يبقى في صورة g(n) (ده مسموح لأننا بنقول ≤)، وبعدين نجمع المعاملات فيطلع c.

1. 4n + 10 = O(n)

Show solution 
4n + 10 ≤ 4n + 10n = 14n   for n ≥ 1   → c = 14, n₀ = 1
10 ≤ 10n لما n ≥ 1، فبدّلنا 10 بـ 10n وجمعنا 4 + 10 = 14.

2. 2n² + 50n + 100 = O(n²)

Show solution 
2n² + 50n + 100 ≤ 2n² + 50n² + 100n² = 152n²   for n ≥ 1   → c = 152, n₀ = 1
50n ≤ 50n² و 100 ≤ 100n² لما n ≥ 1. المعاملات: 2 + 50 + 100 = 152.
غلطة في الكشكول: مكتوب c = 125، والصح 2 + 50 + 100 = 152. (أي c أكبر من 152 كمان صح، بس 125 مع n₀ = 1 غلط: عند n = 1 الطرف الشمال 152.)

3. 5n log n + 20n = O(n log n)

Show solution 
for n ≥ 2, log₂ n ≥ 1, so 20n ≤ 20 n log n
5n log n + 20n ≤ 5n log n + 20n log n = 25 n log n   → c = 25, n₀ = 2
ليه n₀ = 2؟ عند n = 1 الـ log = 0 فـ 20n مش هتبقى ≤ 20 n log n. من n = 2 الـ log₂ n ≥ 1 فينفع نضرب فيه.
ملاحظة: الرقم في الكشكول شكله 29، والجمع الصح 5 + 20 = 25. (29 برضه بتنفع لأنها أكبر، بس 25 هي اللي طالعة من الخطوات.)

4. n² + 3n log n + 1000 = O(n²)

Show solution 
log n ≤ n  →  3n log n ≤ 3n² ;   1000 ≤ 1000n²
n² + 3n log n + 1000 ≤ 1004n²   for n ≥ 2   → c = 1004, n₀ = 2
الـ log n دايماً أصغر من n، فـ n log n ≤ n². والثابت 1000 ≤ 1000n². المعاملات 1 + 3 + 1000 = 1004.

5. Assignment: n² − 1000 = O(n²)

Show solution 
n² − 1000 ≤ n²   for every n ≥ 1   → c = 1, n₀ = 1
طرح 1000 بيصغّر الدالة، فهي دايماً أقل من n² نفسها. لو الدكتور عايز f(n) تبقى موجبة كمان خدي n₀ = 32 (لأن 32² = 1024 أكبر من 1000).

int low = 0, high = n - 1;
while (low <= high) {
    int mid = (low + high) / 2;
    if (A[mid] == key) return mid;
    else if (A[mid] < key) low = mid + 1;

Divide the problem into halves, solve each half recursively, then combine the answers.قسّمي المشكلة نصين، حلّي كل نص بنفس الطريقة (recursion)، وبعدين ادمجي الإجابتين.

2. Counting inversions in [3, 1, 4, 2, 5]

Show solution

  left  [3, 1]    → (3,1)              = 1   sorted → [1, 3]
  right [4, 2, 5] → (4,2)              = 1   sorted → [2, 4, 5]

الطريقة البطيئة: نقارن كل زوج (n² مقارنة). الطريقة السريعة زي الـ merge sort: نعدّ جوّه الشمال، وجوّه اليمين، وبعدين أثناء الدمج نعدّ الأزواج اللي واحد منها في كل ناحية. وإحنا بندمج [1, 3] مع [2, 4, 5]: لما الـ 2 من اليمين تتحط قبل الـ 3 من الشمال، كل اللي فاضل في الشمال (الـ 3) بيعمل inversion معاها.

3. Maximum subarray of [-2, 1, -3, 4, -1, 2, 1, -5, 4]

Show solution

right half [2, 1, -5, 4]      → best = 4      ([4] at the end)

          best sum starting after the middle right  = 2 + 1     = 3

Loop rules

  • Nested loops multiply; sequential loops add.جوّه بعض = ضرب، ورا بعض = جمع.
  • i = i·2 or i = i/2 (or ×3, /3) → log n.بتضرب أو تقسم = log.
  • i = i + 2 → n/2 → still O(n).بتنط بثابت = n.
  • Inner loop to i → Σi = n(n+1)/2 → n²; inner loop to i·i → Σi² → n³.لحد i = n²، لحد i² = n³.
  • A loop of n iterations: condition tested n + 1 times, body n times.الشرط n+1، والجسم n.

  f(n) bigger (by n^ε) + regular →  Θ(f(n))
  differ only by lg n            →  basic master can't (extended: ×lg)
